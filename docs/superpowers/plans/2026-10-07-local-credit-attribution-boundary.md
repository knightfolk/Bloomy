# Verified local credit boundary

The native UI must keep account credit history useful without treating another
owned machine's credits as this Mac's earnings. Current source requests account
reports with no provider filter; that is appropriate for gross account views,
but cannot calibrate local serving rates, electricity-adjusted profit or swaps.

1. Add a distinct typed local-provider report capability to the authenticated
   client protocol. Its default is unavailable; a caller-selected provider-ID
   filter is not verification. Restrict construction to the telemetry module.
2. Route local power matching, serving calibration and the profit chart through
   that capability, with the existing context/epoch publication checks. Account
   gross charts still read one atomic account report. Synthetic fixtures opt in
   explicitly; production does not fabricate an association.
3. Clarify account scope in visible graphics and provide concise local-profit
   unavailable guidance. Retained account charts cannot masquerade as local
   profit when a metric changes or attribution is absent.
4. Verify regressions for unqualified, single-provider and misleading model/ID
   evidence, accepted inert local reports, session changes and held callbacks.
   Inspect optimized native unavailable/recovery behavior and compact layouts;
   complete required tests, builds, review and a normal source checkpoint.

Provider identity findings: installed CLI 0.9.17 and current daemon field names
provide no coordinator provider UUID. Historical local upstream 0.8.16 generates
connection UUIDs; its doctor signer lookup does not prove durable credit-history
ownership across reconnects. New source/API proof is required before adding a
production resolver. Preserve exact ledger provider IDs, credentials and local
configuration; do not start the provider or perform inference for this work.

This implements an evidence boundary, not the missing resolver. The broader
native polish goal, real machine attribution and existing motion gates stay open.
