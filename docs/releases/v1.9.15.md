# Bloomy v1.9.15

Bloomy does less background work while keeping monitoring and local history active. Token averages update when measurements change, model cards share demand calculations, and hidden popup and Metrics views stop their display work. Fan panels share one polling loop, with fewer background checks for unchanged provider settings.

Electricity readings now save individually to an incremental local journal. Existing JSON history is imported safely and retained as a backup. Storage failures, missing readings, and measurement gaps remain explicit. Performance history also uses faster chronological queries and retention checks.

Long continuous model visits no longer incur repeated array copies. Aggregate Metrics refreshes every 30 seconds while visible, with immediate manual refresh and period changes. Switches and request counters are still recorded immediately.

Settings and keyboard shortcuts now open the same dashboard window, preserving its selected page and staged provider changes. Contextual update and electricity links open their matching settings page. Native Edit and Window menus remain available, with View → Enter Full Screen and Help → Bloomy Help opening the existing Support page.

Models can show saved capacity limits even when the live catalog cannot load. These are explicitly saved choices, with unavailable or stale reads identified; editing and applying still require a verified catalog.

Saved-key checks run in the background without reading the secret just to display setup status. Chat and Nudge distinguish a pending or unavailable check from a missing key, so opening the app does not hold up the interface or send you through setup again. Actual requests retain their key validation.

Local performance metrics recognize Darkbloom 0.9.17's model-inventory refresh state. Provider configuration, Autopilot enrollment, and running models are preserved during the app update.
